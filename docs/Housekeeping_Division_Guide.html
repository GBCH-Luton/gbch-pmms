🏢 What "Housekeeping" is

A full division, same standing as Maintenance and Compliance — its own nav item, its own scoped managers, its own slice of Pipeline/Reports/Sign-Off. Not a bolt-on to Maintenance.

🗂️ The 4 categories routed to it

Any ticket in one of these categories is automatically Housekeeping's, no manual division picker involved:

Cleaning Rota Housekeeping & Cleaning Pest Control Rubbish & Clearance

👥 The two roles

Housekeeping Manager (division-scoped manager access) and Housekeeper (division-scoped builder access) — both are Custom Roles set up under Admin → Access & Roles. See the Setup track for exactly how.

🔁 Its one automatic engine

A daily background job creates a "Routine 2-Week Visit" ticket for every property with a cleaner assigned, once it's overdue — the only division in PMMS where tickets can create themselves.

This is exactly what a Housekeeper sees on their phone — the same app every builder uses, with two extra bits that only appear on a Routine 2-Week Visit job: reporting a delay, and a completion checklist.

4 Reviewing a delay reason

Whenever a Housekeeper submits a delay on a Routine Visit (see Housekeeper track, step 5), it lands here, oldest first, until a manager acts on it.

  • Approve or Reject — either way, the cleaner gets a notification and it's logged to the ticket's audit trail.
  • Rejecting doesn't undo anything automatically — it just tells the cleaner to speak to their manager; the ticket itself is untouched.

5 Assigning a cleaner to a property

On the property's Core tab — the "Assigned Cleaner" section. Click Assign (or Reassign), pick a Housekeeper from the dropdown, save.

  • Saving stamps today as the property's cleaning baseline — the 12-day countdown to its first automatic visit starts from here.
  • If the property's Staff Gender Restriction (Restrictions tab, labelled "Support Worker Restrictions" — a name held over from an earlier feature, not Housekeeping-specific wording) is set to Male Only or Female Only, the dropdown only offers Housekeepers whose own gender field matches. A Housekeeper with no gender set on their staff record is treated as "don't offer" on a restricted property.

6 What a Housekeeping Manager sees on a property

Only two tabs: Core (which itself is stripped down to just a vulnerable-occupant warning, read-only, plus the Assigned Cleaner section) and Restrictions, also read-only for this role.

Every other property tab — Compliance, Assets, Maintenance, Lease & Legal, Documents, Notes, Rooms, Gardens — simply isn't shown. This is a UI-level restriction, not a database-level one; a Housekeeping Manager's underlying access isn't narrower, the page just doesn't offer those tabs.

7 Raising an ad-hoc Housekeeping ticket

Anything that isn't the automatic routine visit — a one-off mess, a pest sighting, a void that needs clearing — goes through Log a Ticket exactly like any other job. Picking a Housekeeping category routes it to this division automatically; there's no separate division picker to remember.

  • Cleaning Rota → Urgent Clean
  • Housekeeping & Cleaning → Void property clean, Deep clean required, End of tenancy clean, Communal area cleaning, Carpet cleaning, Window cleaning
  • Pest Control → Rodent infestation, Bed bug treatment, Insect infestation, Bird/pigeon issue, Preventative treatment
  • Rubbish & Clearance → Hazardous waste disposal, Fly-tipping removal, Property clearance, Bulk waste removal, Garden waste clearance

It's assigned automatically to whichever eligible Housekeeper currently has the fewest open jobs — same auto-assign logic Maintenance uses, just scoped to Housekeeper-role staff.

8 Pipeline, Reports, Sign-Off — all scoped too

Wherever a Housekeeping Manager looks — Pipeline, Reports, Sign-Off — they only ever see tickets in the 4 Housekeeping categories. This is enforced at the database level (row-level security), not just hidden in the UI, so it holds even if a ticket is opened by a direct link.

pmms.greenbridgehousing.com/sign-off

Sign-Off

Only the person who raised a ticket can archive it.

A Routine 2-Week Visit ticket has no raiser — PMMS created it, not a person — so it currently has nobody able to sign it off. See the note below.

9 Signing off completed work

An ad-hoc Housekeeping ticket (raised by a manager through Log a Ticket) works exactly like any other division: once Completed, it sits in Sign-Off for whoever raised it to review and archive.

A genuine current gap, found while writing this guide, not a design choice: a Routine 2-Week Visit ticket is created by the automatic daily engine, not by a person — so it has no "raised by" on it. PMMS's sign-off rule is "only the raiser can archive it," which for these means nobody currently can — they'll sit in "Completed" indefinitely once a Housekeeper finishes one. This hasn't shown up yet in production simply because no property has crossed the 12-day threshold and had one finished yet.

3 The two roles that already exist

Under Admin → Access & Roles → Roles panel, two custom roles are already set up:

  • Housekeeping Manager — Access Level "Manager", Division "Housekeeping". Gives everything shown in the Manager track above, and nothing outside it.
  • Housekeeper — Access Level "Builder", Division "Housekeeping". Logs in through the same builder app as any other tradesperson (see the Housekeeper track).

Assign either to a real staff member the same way as any role: Admin → Access & Roles → find or add them → set their Role.

Worth knowing: there's also a much older, built-in "Cleaner" role label with no division and no login access at all — a leftover organisational tag, not the same thing as the "Housekeeper" custom role above. Giving someone the built-in "Cleaner" role does not let them log in; "Housekeeper" is what actually grants access.

4 Settings → Routine Cleaning Visits

Three numbers currently live here, all shown at their real, currently-saved values:

  • Flag as due after 12 days — the threshold used both for the Overdue/Due Soon colour tiers and for when the automatic engine creates a new ticket.
  • Estimated minutes: 30 — stamped onto every auto-created visit ticket (there's no manager assignment step to type one in, since nobody assigns these by hand).
  • Alerts enabled: on — a single switch. Turning it off stops the daily engine from creating any new visit tickets at all, portfolio-wide, without touching existing ones.

6 How the automatic engine actually works

There's no screen for this — it's a background job (a scheduled Supabase Edge Function) that runs once daily and quietly creates tickets when they're due, which is why it's shown here as a flow rather than a screenshot.

  • It's safe to run more than once — the duplicate-guard in step 2 means re-running it never creates two open visits for the same property.
  • This is the only place in all of PMMS where a ticket creates itself with no person raising it — which is exactly what causes the Sign-Off gap noted on the Manager track, step 9.
